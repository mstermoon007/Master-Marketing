## 真机创建团队 RLS 报错修复（15:30）

- 现象：真机创建团队报 `new row violates row-level security policy for table "members"`，teams 写入成功、members 被拒。
- 根因①：PG 对 INSERT...RETURNING 的返回行也应用 SELECT 策略；原 members_select 用 is_team_member() 自引用子查询（查 members 自己），同命令快照看不到刚插入的行 → 返回行被过滤 → 42501。teams_select 是 true 所以 teams 永远成功。DB 复现确认。
- 根因②：is_team_member/is_team_manager 均为 SECURITY INVOKER，策略内子查询会再触发 members 自身 RLS → 无限递归（stack depth exceeded）。此前未爆发仅因 members 表一直为空。
- 修复：members_select 改为 `user_id = auth.uid() OR is_team_manager(team_id)`（INSERT RETURNING 直判可见）；两函数 ALTER 为 SECURITY DEFINER SET search_path=public（内部绕过 RLS，终止递归）。
- 回归：5 场景（owner 建团队/新成员加入/成员只见自己+owner 见全队/录入 RETURNING/manager 可见性）全部通过。
- 连带：joinTeam 对停用成员改为显式友好报错；清理孤儿团队 TUL8DHS/T3NQMBU 与复现数据。
- 教训：自引用 RLS 策略必须用 SECURITY DEFINER 辅助函数；写入后带 .select() 的路径都会踩 RETURNING 可见性问题。
