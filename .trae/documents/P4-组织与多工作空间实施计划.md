# P4 · 组织与多工作空间实施计划

## Context

P0–P3 已完成并签收。当前数据模型以单一 `team_id` 为租户边界，`members` 还限制「一人一团队」，无法承载「工作空间 → 部门 → 团队」的组织结构。P4 要在不破坏现有 35 个 action 契约与既有数据的前提下，引入工作空间与部门层级，支持一人多空间切换，并保证跨空间查询被拒绝。

已确认的决策：

- 存量迁移：**每个团队生成一个独立工作空间**，`workspace_code = 'W' + team_id`，名称取「团队名 工作空间」，现有可见范围不变。
- 小程序：**改造 `pages/team` 为空间/团队切换 + 新建/加入入口**，`pages/profile` 增加当前空间与切换入口。
- **只读角色完整实现**：`viewer` 读通、写全拒，管理员入口按有效角色隐藏。

## 1. 数据模型与迁移

### 1.1 新增表（schema.sql 与迁移脚本同步）

| 表 | 关键字段 | 约束 |
|---|---|---|
| `workspaces` | `id CHAR(24)`、`workspace_code VARCHAR(32)`、`name`、`owner_uid`、`config JSON`、`created_at` | `uk_workspaces_code(workspace_code)` |
| `departments` | `id CHAR(24)`、`workspace_id CHAR(24)`、`parent_id CHAR(24) NULL`、`parent_key CHAR(24) GENERATED ALWAYS AS (IFNULL(parent_id,'')) STORED`、`name`、`depth TINYINT`、`leader_uid`、`status`、`created_at` | `uk_dept_ws_parent_name(workspace_id,parent_key,name)`；`idx_dept_ws_parent(workspace_id,parent_id)` |
| `workspace_members` | `id CHAR(24)`、`workspace_id CHAR(24)`、`user_id`、`name`、`role`(owner/admin/member/viewer)、`status`、`joined_at` | `uk_ws_member(workspace_id,user_id)`；`idx_ws_member_user(user_id)` |

### 1.2 现有表扩展

- `teams`：`workspace_id CHAR(24) NULL`、`department_id CHAR(24) NULL`；索引 `idx_teams_workspace(workspace_id)`。不加唯一键（一个空间多团队）。
- `members`：`department_id CHAR(24) NULL`、`left_at VARCHAR(32) NULL`；`role` 扩展为 `owner|manager|member|viewer`。`uk_members_team_user` 保持不变。
- `form_templates` / `daily_entries` / `report_tasks`：增 `workspace_id CHAR(24) NULL` + 复合索引 `(workspace_id, ...)`。
- `audit_logs`：增 `workspace_id CHAR(24) NULL`，`team_id` 改为可空（空间级审计无团队）；索引 `idx_audit_workspace_time(workspace_id,created_at)`。

新增 `server/sql/migrate_p4_workspaces.sql`（部署级、幂等）与 `server/sql/migrate_p4_rollback.sql`：

- 加列/加索引统一用 `information_schema` 判断 + `PREPARE/EXECUTE`（MySQL 8 无 `ADD COLUMN IF NOT EXISTS`）。
- 建空间：`workspaces.id = SUBSTR(SHA2(CONCAT('ws:', team_id),256),1,24)`，`workspace_code='W'+team_id`，`name=CONCAT(name,' 工作空间')`。
- 回填 `teams.workspace_id`，再由 `teams` join 回填模板/录入/任务/审计的 `workspace_id`。
- `workspace_members` 由 `members` 去重生成：同 `(workspace,user)` 用 `ON DUPLICATE KEY UPDATE` 按 `owner > admin > member > viewer` 取高，不降级。
- 收紧 `NOT NULL` 前先检查孤儿行；若有 NULL 不强制，改为自检报警。
- 自检 `SELECT`：teams 缺失 workspace = 0；四张子表 `workspace_id IS NULL` = 0；`workspace_members` 去重数 ≥ `members` 去重数；`departments.depth ≤ 3`。
- 回滚脚本只回滚结构，脚本头注明「有损，先备份」。

`server/app/db.py` 的 `JSON_COLUMNS` 增加三张新表（`workspaces: ["config"]`），使其进入表白名单。

## 2. 服务端权限与组织服务

新增 `server/app/services/org.py`（单点实现，禁止各 handler 自行判断）：

- `team_context(conn, team_id)`：取团队行（含 `workspace_id`/`department_id`）。
- `workspace_role(conn, uid, workspace_id)`：`workspace_members` 中 active 角色。
- `department_leader_scope(conn, uid, workspace_id)`：返回其负责的部门子树（递归 CTE）。
- `can_read_team` / `can_manage_team` / `can_write_team`。
- `effective_role(...)`：团队 owner/manager 优先，其次空间 owner/admin、部门负责人，最后 member/viewer。
- `next_depth(parent_id)`、`assert_move_allowed(dept, new_parent)`：新建深度 ≤3；移动时用子树最大深度判断，禁止挂到自身后代。

改造 `server/app/handlers/common.py`：

- `require_member` / `require_manager` 改为返回**显式访问上下文**，不再伪造成员行：
  `{member: 真实行或 None, membership_id, user_id, team_id, workspace_id, workspace_role, effective_role, is_team_member}`。
- 新增 `require_writer`（viewer 写操作拒绝）、`require_workspace_role`。
- `is_manager(ctx)` 只看 `effective_role in (owner, admin, manager)`。
- `audit()` 增加 `workspace_id` 参数并允许 `team_id=None`；未传时按团队反查。

修复所有依赖 `me["user_id"]` / `me["role"]` / `me["id"]` 的调用点：

- `templates.py` `create_draft` / `publish_template`：写入 `published_by/created_by` 改用 `uid`。
- `tasks.py` `create_report_task`：`created_by` 改用 `uid`。
- `teams.py` `update_team_config`：审计角色改用 `effective_role`。
- `members.py` `update_member` / `remove_member`：自保护改为 `uid == target["user_id"]`；owner 保护用 `effective_role == 'owner'`；角色白名单加入 `viewer`。
- `entries.py` `save_entry`、`audit.log`：改用 `require_writer`，viewer 不能写。

查询隔离：已解析出 `workspace_id` 的列表查询（模板、录入、任务）在 `team_id` 条件旁追加 `AND workspace_id = %s`；所有 INSERT 由服务端写入 `workspace_id`，不接受客户端传值。

## 3. 新增 action（9 个，总数 35 → 44）

| action | 权限 | 说明 |
|---|---|---|
| `listMyWorkspaces` | 登录 | 我所属的空间、空间角色、各空间下我的团队 |
| `switchWorkspace` | 登录 | 入参 `teamId` 或 `workspaceId`，校验后返回 `{workspace, workspaceRole, team, member, teams, departments}`；无团队的空间也可进入 |
| `createWorkspace` | 登录 | 创建空间并成为 owner；可选同时创建首个团队 |
| `updateWorkspace` | 空间 owner/admin | 名称与配置 |
| `listWorkspaceMembers` | 空间 owner/admin | 空间成员与角色 |
| `updateWorkspaceMember` | 空间 owner/admin | 调整角色/状态；角色变更仅 owner |
| `listDepartments` | 空间成员 | 部门树（供空空间与团队归属选择） |
| `createDepartment` | 空间 owner/admin | 新建部门，深度 ≤3 |
| `updateDepartment` | 空间 owner/admin | 重命名/移动/设负责人/停用，移动校验环路与深度 |

既有 action 扩展：

- `createTeam`：新增可选 `workspaceId` / `departmentId`；取消「一人一团队」拦截，改为「同团队不可重复加入」；不传空间时自动创建「团队名 工作空间」，保证每个团队都有空间。
- `joinTeam`：自动补 `workspace_members`（缺失时插入，不降级已有角色）；`members.left_at` 非空则复用原行重新激活，不 INSERT。
- `getMyMember`：支持可选 `teamId`；返回真实成员并附加 `workspace_id/workspace_role/effective_role`。
- `updateTeamConfig`：支持 `departmentId`（校验同空间，仅空间 owner/admin 可改）。
- `expected.load_active_members`：排除 `role='viewer'`（只读成员不参与应提交口径）。

## 8. 风险与边界

- **不改** `daily_entries.form_data`、`uk_entry_team_user_date`、`uk_task_team_key`、`uk_tpl_team_id_ver` 的语义。
- **不改** 分析引擎指标/规则口径；`analysis_*` 表本期不加 `workspace_id`，隔离在 action 入口经 team→workspace 校验保证。
- 空间级审计使 `audit_logs.team_id` 可空，属结构变更，需在回滚说明中标注。
- 存量迁移 DDL 会锁表，部署窗口需低峰执行；脚本头要求先备份。
- 不做：Web 后台、扫码登录、空间共享模板、跨空间分析对比（属 P5/P6）。
